# AGENTS.md — 개발 AI 작업 규칙

> 프로젝트: **회사1** · 설계 버전: **v3.1.1** · spec-format v2  
> 개발 AI가 맨 먼저 읽는 문서다. 읽는 순서와 작업 규칙은 `AGENTS.md`.

## 1. 이 스펙으로 만들 것

- 사업: 회사1
- 개발 대상: 기능 245개 · 테이블 167개 · API 544개
- 기술 스택: TypeScript · NestJS · PostgreSQL 16 · Next.js 14 · React 18 · TypeScript (확정 — 기능 명세에서 고름 TQ-001) — `ARCHITECTURE.md` 2절

## 2. 읽는 순서

| 순서 | 문서 | 내용 |
|---|---|---|
| 1 | PRD.md | 무엇을 왜 만드는지, 범위, 비기능 요구사항, 미확정 사항 |
| 2 | ARCHITECTURE.md | 기술 스택, 모듈, 외부 연계, 보안, 성능, 배포 제약 |
| 3 | DATABASE.md + schema.sql | 테이블·관계·업무 제약 (schema.sql이 기준) |
| 4 | API.md + openapi.yaml | 기능별 API (openapi.yaml이 기준) |
| 5 | BEHAVIOR.md | 상태 전환, 자동 처리, 값의 출처 |
| 6 | ACCEPTANCE_CRITERIA.md | 완료 판정 기준 (AC ID = 테스트 이름) |
| 7 | TASKS.md | 작업 순서와 작업별 완료 기준 |
| 8 | DECISIONS.md | 결정의 이유와 아직 가정인 것 |

## 3. 지킬 원칙

1. 스펙에 없는 기능·테이블·컬럼·API를 만들지 않는다. 필요해 보이면 만들지 말고 `TODO(질문)`으로 남겨 작업 보고에 적는다.
2. DB는 `schema.sql`을 그대로 만든다. 테이블·컬럼 이름을 바꾸지 않는다. 이름: 설계 이름 그대로 (영문 snake_case).
3. API는 `openapi.yaml`과 같게 만든다 (경로·메서드·필드 이름·타입·오류 코드). 필드의 `x-db-column`이 저장·조회할 컬럼이다.
4. 업무 규칙 앞 표시에 따라 구현한다.

| 표시 | 뜻 | 구현 |
|---|---|---|
| 표시 없음 · (결정 …) | 확정 | 그대로 구현 |
| (가정) | 근거 없이 정한 값 | 구현하되 값은 설정으로 빼고 주석에 '가정' |
| (확인 필요 …) | 고객 답 대기 | 구현하지 않고 `TODO(질문 ID)`. 그 규칙의 테스트도 보류 |
| (공통 P…) | 여러 기능이 같이 쓰는 규칙 | 공통 모듈 한 곳에 구현하고 기능에서 불러 쓴다 |

5. 상태 변경·자동 처리·요청에 없는 값은 `BEHAVIOR.md`대로 구현한다. 근거가 '확인 필요'인 항목은 구현하지 않고 `TODO(질문 ID)`로 둔다.
6. 보안: `*_hash` 컬럼은 단방향 해시(비밀번호는 비밀번호 전용 해시), `*_enc` 컬럼은 암호화해 저장한다. 평문 비밀값을 로그·응답에 남기지 않는다.
7. 스펙 문서는 고치지 않는다. 스펙과 코드가 다르면 코드를 스펙에 맞추고, 스펙이 틀렸다고 보이면 질문으로 남긴다.

## 4. 작업 방식

1. `TASKS.md` 순서대로 한 작업씩 한다. 선행 작업이 끝나야 시작한다.
2. 작업의 완료 기준(AC) 테스트를 먼저 쓰고 구현한다.
3. 완료 = 그 작업의 AC 테스트와 기존 테스트가 모두 통과.
4. 커밋 메시지와 테스트 이름에 작업·기능 ID를 붙인다 (예: `TASK-007 FN-SFR-001-01 서비스 요청 등록`).

## 5. ID 규칙

| ID | 뜻 |
|---|---|
| 원문 번호 기반 (예: SFR-001-01) | 요구사항 (`PRD.md`) |
| FN-… | 기능 (기능 명세 `functions.md`) |
| AC-… | 수용 기준 (`ACCEPTANCE_CRITERIA.md`) |
| TASK-… | 작업 (`TASKS.md`) |
| ADR-… | 결정 기록 (`DECISIONS.md`) |
| Q-·RC-·CF-·FQ-·DQ-·TQ- | 고객 확인 질문 (요구사항·요구사항 검토·충돌·기능 명세·데이터 설계·개발 스펙) |
